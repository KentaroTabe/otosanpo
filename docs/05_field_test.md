# 05. フィールドテストの進め方

実機 + AirPods でしか確認できない挙動(位置精度・ヘッドフォンモーション・音の定位)を
段階を分けて確認し、閾値調整の材料をフィールドログとして残す。

## ログの取り出し

散歩中は画面を見られないため、判断材料は端末内の TSV(`otosanpo-field-log.tsv`)に追記している。
取り出しは**実機を操作しない経路**を既定とする。

1. iPhone のアプリ > フィールドログ > **「ログを書き出す」** > AirDrop で Mac へ
2. 受信したファイルを `field-logs/inbox/` に入れる(Finder でドラッグ)
3. `scripts/import_log.sh` を実行

`import_log.sh` は `field-logs/` の中だけで完結する。`~/Downloads` など PC の他のフォルダは
読まないし変更しない。取り込んだファイルは inbox から `field-logs/field-log-<書き出し日時>.tsv`
へ移動する(残すと次回に前回のログを読んでしまうため)。

- 取り込みと同時に `scripts/summarize_log.sh` で要約を出す。ログは帰路ビーコンだけで数百行になり、
  そのままでは判断に要る行が埋もれるため
- 要約の方針: 判断材料になる行(状態遷移・提案・ジェスチャ振幅・方向の取得元)は全件、
  量が多く 1 行ずつには意味の薄い行(ビーコン)は間引いて傾向だけ
- `scripts/summarize_log.sh <ファイル>` で取り込み済みのログを再要約できる
- USB 接続の実機から直接取り出す `--usb` も残してあるが、実機に触れるため既定では使わない
  (CLAUDE.md「実機へのインストールと起動は人が Xcode から行う」)
- テストの区切りではアプリ内の「ログを消去」を押してから歩き始める。セッションの切り分けが楽になる

## 2026-08-16 のテストで出た課題

段階 3・4 を 1 回の散歩で実施。時間到来は 2 回発火し(1 回目は延長)、提案音・ジェスチャ応答・
帰路ビーコンはいずれも鳴った。以下は精度・体験の課題であり、詳細と対処方針は各ドキュメントに置く。

- 提案が曲がれない場所で鳴る(10 m 手前・私有地) → docs/04「曲がれない場所で鳴る問題」
- 同じ道の折り返し指示、太い道路の横断コスト → docs/04「歩ける道とのマッチング」
- 軽いうなずきが検出されない(首振りは 1 回で検出) → docs/04「頭ジェスチャ検出」
- ビーコンが歩調と無関係、角を曲がってから方向反映まで 1〜2 音遅れる → docs/03「ビーコンの距離・方向キュー」
- 顔の向きと進行方向のずれ、方向が実質 3 択 → docs/01 ロードマップ P1/P2

### ログを読んで初めて分かったこと

体感では「方向の反映が遅れる」と見えていたものに、別の原因が混ざっていた。

- **コンパス退避が逆側の定位を出していた**。方向判定 194 回のうち 38 回が退避で、
  帰路の 2 例で左右が反転していた → docs/04。`allow_compass_fallback` を false にした
- **提案が 4 分間に 9 回、すべて「右」方向で鳴っていた**(05:42〜05:45)。この間 `bias` は
  1.00(最大の帰宅寄せ)、`許容` は 175 m → 0 m まで縮んでおり、実質「引き返せ」を
  25 秒ごとに繰り返していた。予算を使い切った状態に別の伝え方が無く、同じ提案を
  鳴らし続ける構造になっている(未対処)
- **AirPods の接続が歩行中に 6 回途切れて復帰していた**(05:46・05:50・05:51・05:52 に集中)。
  **不具合ではなく、人と会話するために外した**ことによる(本人確認済み)。装着検出は
  意図どおり動いている。ただし外している間はジェスチャを受け付けられないため、
  応答待ち中に外れた場合の扱い(再装着まで待つか、時間切れとするか)は未整理

## 段階 5 の観察項目

閾値調整後の通し確認。手順は段階 3・4 と同じ(ログ消去 → 10 分 → 開始 → 時間到来で
うなずき → ビーコンで帰宅 → ログを書き出して inbox へ)。今回の変更に対応する観察点:

1. **軽いうなずきが通るか**(`nod_pitch_threshold_deg` ±10° → ±8°)。
   通らなければ、はっきりうなずいた場合との差をログで比較する
2. **応答待ち中に、うなずいていないのに帰路が始まらないか**。始まったら ±10° に戻す。
   これが今回の変更で最も見たいこと
3. **ビーコンが中央でばかり鳴らないか**(コンパス退避の無効化)。左右が付く頻度が落ちすぎて
   案内として成立しないなら、course のホールドを実装する
4. 角を曲がった後、何音目で左右が反映されるか(退避を切った状態での純粋な遅れの量)
5. 応答待ちの最中に AirPods を外した場合どうなるか(会話などで外すのは通常の使い方。
   再装着すれば応答できるのか、60 秒の応答待ちが先に切れるのか)
