# 01. コンセプトと決定事項

## アイデア概要

**タイトル**: 音でそっと導く、画面を見ない寄り道散歩アプリ

**説明**: スマホを画面ではなく音で操る散歩アプリ。出発前に時間だけ決めれば、歩行中は短い効果音が普段通らない道への寄り道を提案する。時間が来たら音で知らせ、うなずきで帰路開始、首振りで延長を選択。帰路同意後は確認音がしばらく鳴り、その後は方向ビーコン音が自宅へ導く。移動履歴は端末内のみで学習し、通勤路は自動で除外される。

## ゴール(最終的な目的地)

「散歩に出る心理的ハードルを下げる」ことが最終目的。行き先を考える負担・迷う不安・スマホを見続ける煩わしさの 3 つを取り除き、**AirPods と iPhone だけで、視覚 UI に一切触れずに 30 分の散歩が成立する**状態を App Store 公開レベルで実現する。

## 3 原則

1. **画面を見ない** — 散歩中の能動操作はゼロ。入出力は音と頭のジェスチャのみ
2. **叱らない** — 提案は無視してよい。時間超過しても急かさず、一度だけ静かに聞く
3. **約束を守る** — どの瞬間でも「そこから帰ると何分か」が予算内に収まるよう内部で保証する

## 決定事項(検討の経緯から)

| 論点 | 決定 | 理由・補足 |
|---|---|---|
| 対象環境 | iPhone + AirPods | ヘッドフォンモーションと外音取り込みが前提 |
| 散歩中の操作 | なし。時間は事前設定 | AirPods ステムはサードパーティ再割当不可。ボタン操作自体を排除 |
| 寄り道(コンビニ等) | アプリを開いて対応(例外的に画面を許容) | 要求の裾野が広く、無画面で網羅できないため |
| 時間到来時の応答 | 頭ジェスチャ(うなずき=帰路開始 / 首振り=延長) | CMHeadphoneMotionManager で検出。promptingReturn 状態のみ有効 |
| 音の基本方針 | 基本無音・外音取り込み・「点」の earcon | 安全(環境音マスク回避)・飽き防止・ユーザーの音楽が主役 |
| 帰路同意の確認 | 同意後しばらく確認音(returnAck)を繰り返す | 「同意が伝わったか」の不安を解消(ユーザー要望) |
| 帰路中の通知 | 控えめな間欠ビーコンのみ。「帰宅中」を意識させない | 近いほど間隔が短くなる(ガイガーカウンター方式) |
| 空間表現 | 左右パン + 間隔変化(HRTF 非依存) | HRTF は前後混同が起きやすい。MVP は確実な手がかりに絞る |
| 履歴データ | 端末内で完結。送信ゼロ | 位置情報アプリとしての信頼の根拠 |
| 通勤路の除外 | 「学習モード」を補助輪とし、以後はセル通過カウンタ + 指数減衰 | なぞり UI は完成品で追加。半減期で古い道は自動的に新鮮さが戻る |
| 帰宅予算 | ゴムひもモデル(許容半径 + 帰宅方向バイアス) | 事前時間設定・無指定の両方を単一モデルで扱える |

## スコープ

- **プロトタイプ(約 10 時間・本リポジトリ)**: 上記の全ループが実機で一応動く状態。音はコード合成のサイン波、経路データは自前グリッドのみ(OSM 不使用)
- **完成品(約 1 ヶ月)**: 下記ロードマップ

## ロードマップ

### P0: フィールドテスト(プロトタイプの検証)
1. 実機ビルド、権限フローの確認
2. 自宅設定 → 30 分歩く → ジェスチャ応答 → ビーコンで帰宅、を通しで体験
3. earcon の音量・間隔、ジェスチャ閾値を parameters.json で調整

### P1: 体験の質(1〜2 週目)
- earcon の音デザイン差し替え(CC0 か自作。シームレスな短音)
- ジェスチャ閾値の実測チューニング、誤検出ログの収集
- ビーコンの距離キュー拡張(音量 + ローパス + リバーブ。PHASE の検討)

### P2: 経路知能(3〜4 週目)
- OSM way ベースの経路グラフ(歩道の有無・公園・水辺のスコアリング)
- 地図をなぞる通勤路登録 UI(オンボーディングの補助輪)
- 交差点接近の検出による提案タイミングの精緻化(タイマー駆動からの脱却)

### P3: 仕上げ
- Siri / App Intents(「寄り道したい」等の音声要求)
- HealthKit 連携、バックグラウンド安定化、App Store 提出
