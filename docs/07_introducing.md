# 07. 人に紹介するときの道具

**このアプリは見るものが無い。** 画面を見ずに歩くのが前提なので、スクリーンショットには
設定画面しか写らず、動画には歩いている人しか写らない。**人に渡せるのは音そのものだけ。**

## 作るもの

```
scripts/build_demo.sh          # 音を書き出す(WAV + 鳴った音の記録 JSON)
scripts/build_intro_page.py    # 紹介ページを組み立てる(音を data: URI で埋め込む)
scripts/intro_page.html        # ページの雛形。文言と見た目はここ
```

出力は `build-demo/`(gitignore)。

```
scripts/build_demo.sh
scripts/build_intro_page.py build-demo build-demo/intro.html
```

## 音は**アプリと同じコードで**鳴らす

紹介した音と実物が食い違うと意味がないので、`Sources/Demo`(macOS ツール)は
アプリと同じものを使う。

| 使うもの | 何を決めるか |
|---|---|
| `ToneRenderer`(Core) | 音色 |
| `TurnGuidance`(Core) | 誘導の組み立て(予告・音量・向き・終端) |
| `BeaconRhythm`(Core) | ビーコンの間隔と音量 |
| `config/parameters.json` | 設定値 |

このために**波形合成を Services から Core へ移した**(2026-08-20)。
`EarconSynth` は `AVAudioPCMBuffer` に載せるだけになり、
「Services にロジックを持たせない」(CLAUDE.md)にも沿う形になった。

### 実機との違いは定位だけ

実機は HRTF で 3D に置くが、書き出しは**ステレオパン**。
左右・音量・間隔は忠実で、前後だけ再現しない。前後は実機でも判別できないと
2026-08-18 に確定しているので、失うものは無い。ページにもその旨を書いてある。

## 媒体は Artifact(URL 1 つ)

リンクを送るだけで、相手はスマホでヘッドフォンを付けて再生できる。
インストールも地図ファイルも要らない。既定で非公開なので、共有するかは本人が決める。

音声ファイル単体も併せて渡せる(LINE などで直接送りたい場合)。

- **外部ホストからは読めない。** Artifact は CSP で塞ぐので、音は data: URI で埋め込む
- 上限 16 MB。音は最高 1175 Hz なので **11.025 kHz** で書き出せば足りる
  (必要なのは 2350 Hz 以上)。この設定で 3 場面 + 語彙 5 種を入れて 4.4 MB
- 場面が長いと埋め込みが膨らむ。帰路は「遠い」「近い」の短い 2 本に分けた。
  240 m を歩き切ると 3 分以上かかり、そのまま録ると音量差が伝わる前に飽きる。
  **短い 2 本を並べて聴かせるほうが違いは分かる**

## ページに載せたもの

1. 一行で何か
2. **ヘッドフォンの注意**(左右で方向を伝えるので、これが無いと体験が成立しない)
3. 散策の場面 — 35 m 先の角を右へ(37 秒)
4. 帰路の場面 — 遠いとき(20 秒)/ 近くと到着(17 秒)
5. 音の語彙 5 種 — 1 つずつ再生
6. 3 原則

各場面には**鳴った音の並び**を図で添えた(横が時間、縦が左右、バーの高さが音量)。
音だけの製品なので、聴きながら見る手がかりがあると分かりやすい。
図のデータはツールが `scenes.json` に吐いたもので、作り物ではない。

## プライバシー

**座標・地図・経路は一切出力しない。** ツールの入力は `parameters.json` だけで、
出るのは波形と「時刻・左右・音量」の並びのみ。フィールドログも読まない。
