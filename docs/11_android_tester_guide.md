# 11. テスターの手順書(Android)

**このアプリは画面を見ずに歩くもの**なので、スクリーンショットでは何も伝わらない。
実際に歩いてもらうしかない。

**iOS 版と違い、ビルドは要らない。** APK を受け取って入れるだけ
(iOS は無料の Apple ID では配布ができず、テスターに Mac でビルドしてもらう必要がある。
その事情は docs/09、Android で楽になる理由は docs/10)。

所要時間の目安: **準備 5〜10 分 + 散歩 20〜30 分**。

> **重要: この Android 版はまだ実機で 1 度も動かしていません。**
> ビルドが通っていることしか確かめられていないので、**最初は「起動して 5 分歩く」だけ**を
> お願いします。落ちる・鳴らない・進まないといったことがあれば、それ自体が結果です。

## 0. 用意するもの

| | 要否 | 補足 |
|---|---|---|
| Android 端末(10 / API 29 以降) | **必須** | GPS が要る |
| イヤホン・ヘッドフォン | **必須** | 左右で方向を伝えるので、これが無いと体験が成立しない |
| APK(`app-debug.apk`) | **必須** | 開発者から受け取る |
| 経路データ(`otosanpo-map.json`) | 推奨 | **開発者が作って渡す**。無くても動くが提案の質が落ちる |

**歩ける場所**: 車の少ない住宅街や公園まわりが向く。

## 1. 入れる

1. 受け取った `app-debug.apk` を端末で開く
2. 「提供元不明のアプリ」「この提供元のアプリを許可」を求められたら許可する
   (Play ストアを通していないため。**開発中のアプリなのでストアには出していない**)
3. インストールして起動

## 2. 経路データを入れる(推奨)

経路データがあると、**実在する分岐から提案し、帰路を道なりに案内する**ようになる。
無い場合はセル単位の推測だけで動くので、「道の無い方向」を指すことがある。

**作るのは開発者側**(PC で OSM から切り出す)。受け取ったら:

1. `otosanpo-map.json` を端末にコピーする
2. 置き場所は **`Android/data/dev.otosanpo/files/`**
   - PC に USB で繋いで、ファイル転送モードにすると開ける
   - 端末だけで済ませたい場合は、標準の「ファイル」アプリから同じ場所へ

アプリの画面に `地図: 半径5km・2026-08-21` と出れば読めている。`地図: 未読込` なら入っていない。

> 開発者へ: `scripts/build_map.sh <地域データ> <中心緯度> <中心経度>` で作る。
> **相手の散歩の中心(自宅など)の座標が要る**ので、聞くか、だいたいの地点で作る。

## 3. 散歩する

### 出発前

1. アプリを起動し、**位置情報**・**身体活動**・**通知**を許可する
   - 位置情報は「アプリの使用中のみ」で足りる
   - 身体活動は歩調(音の間隔を歩みに合わせる)に使う
   - 通知は常駐の表示に使う(Android は画面を消して動かすのに常駐が要る)
2. イヤホンを付ける。**外音取り込みがある機種はオンにする**(安全のため)
3. 自宅(出発点)で「自宅を現在地に設定」。初回は「ここを自宅にして散歩を開始」でもよい
4. 散歩時間を決める(既定 30 分)
5. 「散歩を開始」を押す。**時間帯に応じた一言が出る**ので、閉じて端末をポケットへ
6. 以後は画面を見ない

### 歩いている間に鳴る音(5 種)

| 音 | 意味 | いつ |
|---|---|---|
| 上行する 2 音(880→1175 Hz) | **こちらへ曲がると新しい道** | 前方 35 m 以内の交差点に近づいた時。角に近づくほど大きくなる |
| 上行する 3 音 | **時間になった。帰る?** | 「今から帰れば時間ちょうど」の瞬間 |
| 下行する 2 音(長め) | **帰路開始を受け付けた** | 「帰る」を選んだ直後 |
| 単発のピップ(440 Hz) | **帰る方向はこちら** | 帰路の間。歩調に同期して鳴り、自宅に近いほど大きい |
| 上行する 3 音(短い) | **到着** | 自宅 10 m 以内 |

- **提案は無視してよい。** 従わなくても叱られないし、鳴り続けもしない
- 曲がる案内は**音の鳴る方に歩けば角に着く**ように作ってある。1 音目だけは
  「どちらへ曲がるか」を指す
- 帰路は角も自宅も同じ音。連続音なら「次の角」、間欠音なら「自宅の方向」

### 時間が来たら — **音量ボタンで答える**

上行 3 音が鳴ったら、**ポケットに入れたまま**:

- **音量↓ = 帰る**
- **音量↑ = 延長**(設定時間の 1/3。最大 2 回)

> iOS 版は AirPods のうなずき・首振りで答えるが、**Android にはヘッドフォンの
> 頭の向きを取る方法が無い**(docs/10)。音量ボタンはその代わり。
> 画面のボタン(「帰る」「延長」)も残してあるので、効かなければそちらで。

反応しなければ 60 秒ごとに鳴り直す。

## 4. 帰ってきたら

### 記録を見る

アプリの「**前回の散歩(開発用)**」に、距離・時間・イベント数と、
案内の終わり方の内訳(曲がり終えた / 従わなかった / 角から離れた)が出る。

> iOS 版にはイベント番号つきの経路図があるが、**Android 版はまだ数字だけ**。
> 図が要るとなったら足す。

### ログを渡す

「**ログをダウンロードへ書き出す**」を押すと、端末の「ダウンロード」に
`otosanpo-field-log-<日時>.tsv` ができる。標準のファイルアプリから共有できる。

次のテストの前に「ログを消去」を押しておくと、回ごとの切り分けが楽になる。

## 5. 感想の返し方

### 先に読んでほしいこと(プライバシー)

**フィールドログには緯度経度が入る。自宅の座標も含まれる。**

- 渡す相手は開発者本人に限る。**公開の場所に貼らないこと**
- 出したくない場合は「渡さない」でよい。**文章の感想だけでも十分**役に立つ
- アプリは通信を一切しない。記録は端末から出ない(出すのは自分で書き出したときだけ)

### 何を書いてほしいか

**うまく言葉にできなくてよい。** 「なんか気持ち悪かった」で十分。特に知りたいのは:

1. **そもそも動いたか。** 落ちなかったか、音が鳴ったか(**今回はここが最重要**)
2. **音のする方へ歩けたか。** 迷ったか、自然に曲がれたか
3. **左右が分かったか**
4. **距離が分かったか**(音量で表している)
5. うるさかった / 静かすぎた場面
6. 音量ボタンでの応答は使いやすかったか
7. 道の無い方向・私有地・危ない方向を指した場面

## 6. 安全について

- **外音取り込みがあれば使う。** 耳を塞ぐと環境音が聞こえにくい
- 提案は**歩ける道かどうかを地図で見ているだけ**で、交通量や工事は考慮していない。
  **従うかどうかは自分で判断する**
- 夜間・雨天・不慣れな土地での初回テストは避ける
- 画面を見ながら歩かない(そもそも見ない設計)

## 7. うまくいかないとき

| 症状 | 見るところ |
|---|---|
| インストールできない | 「提供元不明のアプリ」の許可。Android 10 未満では入らない |
| 起動して「設定ファイルを読み込めません」 | ビルドの不備。開発者へ連絡(APK を作り直す) |
| 音が鳴らない | イヤホンの接続。画面の「提案音 左 / 右」を押して単発の音を確認 |
| 提案が 1 度も鳴らない | 「地図:」の表示。`未読込` なら手順 2。初回の散歩は全方向が未踏で「直進が最良」になりやすく、鳴らないことがある |
| 現在地が取れない | 位置情報の許可。屋外で空が見える場所で数十秒待つ |
| 画面を消すと止まる | 通知に「散歩中」が出ているか。機種によっては電池の最適化から除外する必要がある |
| 音量ボタンが効かない | アプリを画面に出した状態でのみ効く。ポケットの中で画面が消えている場合は、いったん画面を点けて押す |

## 8. いまの状態(期待値の調整)

**プロトタイプであって製品ではない。** 分かっている制限:

- **実機で 1 度も動かしていない**(2026-08-25 時点)
- 音はコード合成のサイン波。**デザインされた音ではない**
- **頭の向きは反映しない。** 首を振っても音は動かない
- 前後は聴き分けられない。真後ろは音色を暗くして代替している
- 経路図(イベント番号つき)は iOS 版だけ
- 画面を消したままの長時間動作は未検証

**それでも「音の鳴る方に歩くと面白い散歩ができる」かどうかが、この試作で確かめたいこと。**
