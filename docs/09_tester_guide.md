# 09. テスターの手順書(iPhone)

**このアプリは画面を見ずに歩くもの**なので、スクリーンショットでは何も伝わらない。
実際に歩いてもらうしかない。

**2026-08-26 に Apple Developer Program へ加入したので、TestFlight で配れる。**
テスターに Mac も Xcode も要らない。以前の「自分でビルドする」手順は
付録として残してあるが、通常は不要。

所要時間の目安: **準備 5 分 + 散歩 20〜30 分**。

音だけ先に聴きたい場合は、開発者に紹介ページ(音の入った URL)を頼めば
歩かずに雰囲気は分かる → [docs/07](07_introducing.md)。

## 0. 用意するもの

| | 要否 | 補足 |
|---|---|---|
| iPhone(iOS 17 以降) | **必須** | シミュレータでは音の定位と GPS が確かめられない |
| TestFlight アプリ | **必須** | App Store から無料で入る |
| AirPods(第 3 世代 / Pro / Max) | 推奨 | うなずき・首振りの応答に使う。無い場合は画面のボタンで代替できる |
| 経路データ(`otosanpo-map.json`) | 推奨 | **開発者が作って渡す**。無くても動くが提案の質が落ちる |

**歩ける場所**: 車の少ない住宅街や公園まわりが向く。片側 2 車線以上の道が多い地域だと
横断コストで提案が減る。

## 1. 入れる

1. 開発者から届いた**招待メールかリンク**を iPhone で開く
2. TestFlight アプリが開くので、「インストール」
3. 起動する

**「開発元を信頼」の操作は要らない。** ビルドは 90 日有効で、更新が出れば
TestFlight から通知が来て 1 タップで入れ替わる。

## 2. 経路データを入れる(推奨)

経路データがあると、**実在する分岐から提案し、帰路を道なりに案内する**ようになる。
無い場合はセル単位の推測だけで動くので、「道の無い方向」を指すことがある。

**作るのは開発者側**(PC で OSM から切り出す)。受け取ったら:

1. `otosanpo-map.json` を AirDrop・メール・メッセージなどで iPhone に受け取る
2. 共有メニューから「**"ファイル"に保存**」
3. 保存先に「**この iPhone 内 > OtoSanpo**」を選ぶ

アプリの画面に `地図: 半径5km・2026-08-18` と出れば読めている。`地図: 未読込` なら入っていない。

> 開発者へ: `scripts/build_map.sh <地域データ> <中心緯度> <中心経度>` で作る。
> **相手の散歩の中心(自宅など)のだいたいの座標が要る**ので、先に断って聞くこと。

## 3. 散歩する

### 出発前

1. アプリを起動し、**位置情報**(アプリの使用中は許可)と**モーション**を許可する
2. AirPods を装着し、**外音取り込み**にする(アプリからは制御できないので手で設定)。
   **安全のため必須と考えてほしい**
3. 自宅(出発点)で「自宅を現在地に設定」。初回は「ここを自宅にして散歩を開始」でもよい
4. 散歩時間を決める(既定 30 分)
5. 「散歩を開始」を押す。**時間帯に応じた一言が出る**ので、閉じて iPhone をポケットへ
6. 以後は画面を見ない

### 歩いている間に鳴る音(5 種)

| 音 | 意味 | いつ |
|---|---|---|
| 上行する 2 音(880→1175 Hz) | **こちらへ曲がると新しい道** | 前方 35 m 以内の交差点に近づいた時。角に近づくほど大きくなる |
| 上行する 3 音 | **時間になった。帰る?** | 「今から帰れば時間ちょうど」の瞬間 |
| 下行する 2 音(長め) | **帰路開始を受け付けた** | うなずきの直後 |
| 単発のピップ(440 Hz) | **帰る方向はこちら** | 帰路の間。歩調に同期して鳴り、自宅に近いほど大きい |
| 上行する 3 音(短い) | **到着** | 自宅 10 m 以内 |

- **提案は無視してよい。** 従わなくても叱られないし、鳴り続けもしない
  (角が背後に回ると止まる)
- 曲がる案内は**音の鳴る方に歩けば角に着く**ように作ってある。
  角に近づくにつれて、音は曲がる先へ移っていく
- 帰路は角も自宅も同じ音で鳴る。連続音なら「次の角」、間欠音なら「自宅の方向」

### 時間が来たら

上行 3 音が鳴ったら:

- **うなずく** → 帰路開始
- **首を振る** → 延長(設定時間の 1/3。最大 2 回)

反応しない場合は 60 秒ごとに鳴り直す。AirPods を外していれば、付け直した時に鳴り直す。
**うまく検出されない時は、ポケットから出して画面のボタンで代替できる。**

## 4. 帰ってきたら

### 経路図を見る

アプリの「**前回の散歩(開発用)**」に距離・時間・イベント数が出る。
「経路図とイベントを見る」を開くと、歩いた経路と**番号を振った案内**が地図になる。

- 灰色の線 = 端末内の経路データの道
- 太い線 = 実際に歩いた経路
- 番号つきの丸 = 曲がる案内。**塗り = 曲がった / 白抜き = 曲がらなかった**
- 丸から伸びる矢印 = その案内が指した向き

**気になったことがあれば、この番号で指してもらえると特定が早い。**
「3 番目の案内が道の無い方を指した」のように書ければ、ログの該当箇所がすぐ出る。

### ログを書き出す

アプリの「フィールドログ > ログを書き出す」から AirDrop などで開発者へ。
次のテストの前には「ログを消去」を押すと、回ごとの切り分けが楽になる。

TestFlight の「フィードバックを送信」からスクリーンショット付きで送ることもできる
(クラッシュした場合は自動で届く)。

## 5. 感想の返し方

### 先に読んでほしいこと(プライバシー)

**フィールドログには緯度経度が入る。自宅の座標も含まれる。**

- ログを渡す相手は開発者本人に限る。**公開の Issue に貼らないこと**
- 出したくない場合は「渡さない」でよい。**文章の感想だけでも十分**役に立つ
- アプリは通信を一切しない。記録は端末から出ない(出すのは自分で書き出したときだけ)

### 何を書いてほしいか

**うまく言葉にできなくてよい。** 「なんか気持ち悪かった」で十分で、
ログと突き合わせれば原因は追える。特に知りたいのは:

1. **音のする方へ歩けたか。** 迷ったか、自然に曲がれたか
2. **左右が分かったか。** 分かりにくい場面があったか
3. **距離が分かったか**(音量で表している)。角の手前で「ここだ」と確定できたか
4. **うるさかったところ / 静かすぎたところ**
5. 帰路は不安なく帰れたか
6. **道の無い方向・私有地・危ない方向**を指した場面(あれば経路図の番号を添えて)

## 6. 安全について

- **外音取り込みを必ず使う。** 音楽と違って断続的だが、耳を塞ぐと環境音が聞こえにくい
- 提案は**歩ける道かどうかを地図で見ているだけ**で、交通量や工事は考慮していない。
  **従うかどうかは自分で判断する**
- 夜間・雨天・不慣れな土地での初回テストは避ける
- 画面を見ながら歩かない(そもそも見ない設計)

## 7. うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 音が全く鳴らない | 画面の「音声: 稼働 / 停止」。停止なら AirPods を繋ぎ直す。「earcon の試聴」で単発の音を確認 |
| 提案が 1 度も鳴らない | 画面の「地図:」表示。`未読込` なら手順 2。初回の散歩は全方向が未踏で「直進が最良」になりやすく、鳴らないことがある |
| 案内が道の無い方を指す | 地図が入っているか。入っていて起きるなら**不具合**なので、経路図の番号を添えて報告 |
| うなずきが効かない | AirPods がモーション対応モデルか。画面の「モーション ○○ Hz」が出ているか。効かなければ画面のボタンで代替 |
| 到着音が鳴らない | 自宅の設定位置と実際の到着位置がずれている可能性。開発者へ連絡(`arrival_radius_m` を広げる) |
| 帰路の案内が来ない | 地図が入っていないと道なりの案内は出ず、自宅を直線で指すビーコンだけになる |

## 8. いまの状態(期待値の調整)

**プロトタイプであって製品ではない。** 分かっている制限:

- 音はコード合成のサイン波。**デザインされた音ではない**
- **頭の向きは反映していない。** 首を振っても音は動かない
  (AirPods の yaw が旋回を追えなかったため。→ [docs/03](03_session_and_audio.md))
- 前後は聴き分けられない。真後ろは音色を暗くして代替している
- ジェスチャの首振り誤検出は約 9%。困るまで直さない方針
- 60 分を超える散歩・バックグラウンド動作の検証は薄い
- アイコンは仮のもの

**それでも「音の鳴る方に歩くと面白い散歩ができる」かどうかが、この試作で確かめたいこと。**

# 付録 A: 配る側の手順(開発者)

## 1 回だけの準備

1. Xcode > Settings > Accounts で Apple ID を追加し、**有料チームが出ることを確認**
2. そのチームの Team ID を入れる:

```bash
scripts/show_teams.sh
```

```bash
scripts/set_team.sh <TEAM_ID>
```

> **個人加入では Team ID が同じまま昇格する。** 「Team ID が変わっていない」ことは
> 「切り替わっていない」根拠にならない(2026-08-26 にこれで判断を誤った)。
>
> **見分けるのはプロファイルの期限。** 有料チームの開発プロファイルは 1 年、
> 無料は 7 日。加入前に作られたプロファイルが期限内だと**そのまま使い回される**ので、
> 加入しても署名が無料のままになる。作り直すには消してからビルドする:
>
> ```bash
> rm ~/Library/Developer/Xcode/UserData/Provisioning\ Profiles/*.mobileprovision
> ```
>
> ```bash
> scripts/build_device.sh
> ```
>
> **配布用の証明書(Apple Distribution)は先に作らなくてよい。** 開発ビルドでは
> 作られず、Organizer の Distribute App の途中で Xcode が作る。

3. App Store Connect でアプリのレコードを作る(バンドル ID は `dev.otosanpo.OtoSanpo`)

## 配るたび

```bash
scripts/archive.sh
```

アーカイブができたら **Xcode > Window > Organizer > Distribute App** で TestFlight へ。
**アップロードはスクリプトでは行わない**(外向きの操作と認証情報が要るため、人が行う)。

- **内部テスター(最大 100 人)は審査なし**で配れる。知り合い数人ならこれが最短
- 外部テスター(最大 10,000 人)は初回に Beta App Review がある
- ビルド番号は `archive.sh` が日時から自動で付ける。同じ番号は 2 度受け付けられない

## 付録 B: 自分でビルドする(TestFlight を使わない場合)

開発者自身が手元の iPhone で試すときの手順。

```bash
git clone https://github.com/KentaroTabe/otosanpo.git
```

```bash
git switch feature/p1-experience
```

```bash
brew install xcodegen
```

```bash
scripts/setup.sh
```

```bash
scripts/build_device.sh
```

iPhone を USB で繋ぎ、**ロックを解除して**「このコンピュータを信頼」を選んでおくこと。
インストールと起動は **Xcode から手で行う**(スクリプトは実機を操作しない方針)。

### 端末に「開発元を信頼」させる

**開発ビルドを新しい端末に入れた初回**、および**アプリが端末から消えた後**は、
この手順が要る(TestFlight で配ったビルドには不要)。

1. **先に Xcode から Run する。**「起動に失敗」と出てもよい —
   インストールは成功しており、**アプリが入っていないと設定に項目が出ない**
2. iPhone で **設定 → 一般 → VPNとデバイス管理**
3. 「デベロッパApp」の下の自分の Apple ID をタップ → 「信頼」
4. もう一度 Run(またはホーム画面のアイコンをタップ)

> **iPhone がインターネットに繋がっていること。** 証明書の検証をオンラインで行うため、
> 圏外・機内モードだと「検証できませんでした」になる。**いちばん多い引っかかり。**

`Verify that the Developer App certificate for your account is trusted on your device`
というエラーはこれ。**ビルドや署名の問題ではない**(2026-08-25 に実際に遭遇。
証明書もプロファイルも有効なままだった)。

> **無料の Apple ID だった頃の注意**(有料プログラムに入った今は該当しない)
> - プロファイルは 7 日で失効し、失効すると「信頼」の項目も端末から消えた
> - 実機を UDID 指定でビルドした時に初めてデバイスがチームに登録された
