# 09. テスターの手順書(iPhone を持っている開発者向け)

**このアプリは画面を見ずに歩くもの**なので、スクリーンショットでは何も伝わらない。
実際に歩いてもらうしかない。ここでは、ビルドから散歩、感想の返し方までを順に書く。

所要時間の目安: **準備 30〜60 分 + 散歩 20〜30 分**。

### なぜ自分でビルドする必要があるのか(配布ビルドが無い理由)

**無料の Apple ID で開発しているため、配って渡す手段が制度上存在しない。**

| 方法 | 必要なもの | 可否 |
|---|---|---|
| App Store | 有料プログラム + 審査 | まだ製品ではない |
| TestFlight | **有料の Apple Developer Program($99/年)** | 使えない |
| Ad Hoc 配布 | 同上 + 端末 UDID の登録(100 台/年) | 使えない |
| 開発者署名で直接インストール | 無料の Apple ID + **その人自身の Mac と Xcode** | **これだけ** |

無料アカウント(Personal Team)は**自分の Apple ID と Mac でしか署名できない**ので、
ビルド済みのものを他人の端末に入れることもできない。プロファイルが 7 日で失効するのも同じ理由。

**Apple Developer Program に加入すれば TestFlight が使え、この節はまるごと不要になる**
(リンクを送るだけ・Mac も Xcode も要らない・ビルドは 90 日有効)。
一方 **Android 版は APK をそのまま渡せる**(有料プログラム不要)ので、
人数を増やしたいときは Android のほうが早い → [docs/10](10_android.md)。

音だけ先に聴きたい場合は、開発者に紹介ページ(音の入った URL)を頼めば
歩かずに雰囲気は分かる → [docs/07](07_introducing.md)。

## 0. 用意するもの

| | 要否 | 補足 |
|---|---|---|
| Mac + Xcode 15 以降 | **必須** | 配布ビルドが無いので自分でビルドする |
| iPhone(iOS 17 以降) | **必須** | シミュレータでは音の定位と GPS が確かめられない |
| Apple ID | **必須** | 無料アカウントで可(下記の制限あり) |
| AirPods(第 3 世代 / Pro / Max) | 推奨 | うなずき・首振りの応答に使う。無い場合は画面のボタンで代替できる |
| OSM の地域データ | 推奨 | 無くても動くが、提案の質が落ちる(手順 2) |

**歩ける場所**: 車の少ない住宅街や公園まわりが向く。片側 2 車線以上の道が多い地域だと
横断コストで提案が減る。

## 1. ビルドして iPhone に入れる

```bash
git clone https://github.com/KentaroTabe/otosanpo.git
```

```bash
git switch feature/p1-experience
```

**ブランチを間違えないこと。** `main` には帰路の案内も散歩の記録も入っていない
(PR #2 以降の約 4,000 行が未取り込み。README のブランチ表を参照)。

```bash
brew install xcodegen
```

```bash
scripts/setup.sh
```

### 署名(Team ID を入れる)

```bash
scripts/show_teams.sh
```

**証明書名の括弧内は開発者 ID であって Team ID ではない。`OU` の値が Team ID。**
出力から自分の Team ID を選んで:

```bash
scripts/set_team.sh <TEAM_ID>
```

`Support/Signing.xcconfig` に書かれる(gitignore 対象なので他人に渡らない)。

### ビルド

iPhone を USB で繋ぎ、**ロックを解除して**「このコンピュータを信頼」を選んでから:

```bash
scripts/build_device.sh
```

`ビルド成功(署名 OK)` と出れば通っている。

**インストールと起動は Xcode から手で行う**(スクリプトは実機を操作しない方針)。
`open OtoSanpo.xcodeproj` して、デバイスを選んで Run。

初回は iPhone 側で **設定 > 一般 > VPN とデバイス管理** から開発元を信頼する。

> **無料の Apple ID の注意**
> - プロファイルは **7 日で失効**する。切れたら Xcode から入れ直す
> - **実機を UDID 指定でビルドした時に初めて**デバイスがチームに登録される。
>   `scripts/build_device.sh` はそれを行う(`generic/platform=iOS` では登録されない)

## 2. 地図データを入れる(推奨)

経路データがあると、**実在する分岐から提案する / 帰路を道なりに案内する**ようになる。
無い場合はセル単位の推測だけで動くので、「道の無い方向」を指すことがある。

1. [Geofabrik](https://download.geofabrik.de/asia/japan.html) から自分の地域の
   `.osm.pbf` か `.gpkg` を落とす(数百 MB〜数 GB)
2. `.osm.pbf` を使う場合のみ `brew install osmium-tool`
3. 散歩の中心(自宅など)の緯度経度を指定して切り出す:

```bash
scripts/build_map.sh ~/Downloads/chubu-latest.osm.pbf 35.681 139.767
```

4. `maps/otosanpo-map.json` ができる。**Finder > iPhone > ファイル > OtoSanpo**
   にドラッグして入れる

アプリの画面に `地図: 半径5km・2026-08-21` と出れば読めている。`地図: 未読込` なら入っていない。

> 落とすのは公開の地域データで、切り出しは手元で行う。**自宅の座標は外に出ない。**
> 生成物は gitignore なので、リポジトリにも入らない。

## 3. 散歩する

### 出発前

1. アプリを起動し、**位置情報**(アプリの使用中は許可)と**モーション**を許可する
2. AirPods を装着し、**外音取り込み**にする(アプリからは制御できないので手で設定)。
   **安全のため必須と考えてほしい**
3. 自宅(出発点)で「自宅を現在地に設定」。初回は「ここを自宅にして散歩を開始」でもよい
4. 散歩時間を決める(既定 30 分)
5. 「散歩を開始」を押し、**iPhone をポケットに入れる。以後は画面を見ない**

### 歩いている間に鳴る音(5 種)

| 音 | 意味 | いつ |
|---|---|---|
| 上行する 2 音(880→1175 Hz) | **こちらへ曲がると新しい道** | 前方 35 m 以内の交差点に近づいた時。角に近づくほど大きくなる |
| 上行する 3 音 | **時間になった。帰る?** | 「今から帰れば時間ちょうど」の瞬間 |
| 下行する 2 音(長め) | **帰路開始を受け付けた** | うなずきの直後 |
| 単発のピップ(440 Hz) | **帰る方向はこちら** | 帰路の間。歩調に同期して鳴り、自宅に近いほど大きい |
| 上行する 3 音(短い) | **到着** | 自宅 10 m 以内 |

- **提案は無視してよい。** 従わなくても叱られないし、鳴り続けもしない
  (角が背後に回ると止まる)
- 曲がる案内は**音の鳴る方に歩けば角に着く**ように作ってある。1 音目だけは
  「どちらへ曲がるか」を指す
- 帰路は角も自宅も同じ音で鳴る。連続音なら「次の角」、間欠音なら「自宅の方向」

### 時間が来たら

上行 3 音が鳴ったら:

- **うなずく** → 帰路開始
- **首を振る** → 延長(設定時間の 1/3。最大 2 回)

反応しない場合は 60 秒ごとに鳴り直す。AirPods を外していれば、付け直した時に鳴り直す。
**うまく検出されない時は、ポケットから出して画面のデバッグボタンで代替できる。**

## 4. 帰ってきたら

### 経路図を見る

アプリの「**前回の散歩(開発用)**」に距離・時間・イベント数が出る。
「経路図とイベントを見る」を開くと、歩いた経路と**番号を振った案内**が地図になる。

- 灰色の線 = 端末内の経路データの道
- 太い線 = 実際に歩いた経路
- 番号つきの丸 = 曲がる案内。**塗り = 曲がった / 白抜き = 曲がらなかった**
- 丸から伸びる矢印 = その案内が指した向き

**気になったことがあれば、この番号で指してもらえると特定が早い。**
「3 番目の案内が道の無い方を指した」のように書ければ、ログの該当箇所がすぐ出る。

### ログを書き出す

アプリの「フィールドログ > ログを書き出す」から AirDrop などで Mac へ。
次のテストの前には「ログを消去」を押すと、回ごとの切り分けが楽になる。

## 5. 感想の返し方

### 先に読んでほしいこと(プライバシー)

**フィールドログには緯度経度が入る。自宅の座標も含まれる。**

- ログを渡す相手は開発者本人に限る。**公開の Issue に貼らないこと**
- 座標を出したくない場合は、**要約だけ**を送ればよい。要約に座標は含まれない:

```bash
scripts/summarize_log.sh <ログファイル>
```

要約だけでも、状態遷移・提案の判定理由・ジェスチャの振幅・音の頻度は読める。
経路長や迂回率の計算には座標が要るので、そこまで見てほしい場合だけログ本体を渡す。

### 何を書いてほしいか

**うまく言葉にできなくてよい。** 「なんか気持ち悪かった」で十分で、
ログと突き合わせれば原因は追える。特に知りたいのは:

1. **音のする方へ歩けたか。** 迷ったか、自然に曲がれたか
2. **左右が分かったか。** 分かりにくい場面があったか
3. **距離が分かったか**(音量で表している)。角の手前で「ここだ」と確定できたか
4. **うるさかったところ / 静かすぎたところ**
5. 帰路は不安なく帰れたか
6. **道の無い方向・私有地・危ない方向**を指した場面(あれば経路図の番号を添えて)

Issue で送る場合は [.github/ISSUE_TEMPLATE](../.github/ISSUE_TEMPLATE) にテンプレートがある。

## 6. 安全について

- **外音取り込みを必ず使う。** 音楽と違って断続的だが、耳を塞ぐと環境音が聞こえにくい
- 提案は**歩ける道かどうかを地図で見ているだけ**で、交通量や工事は考慮していない。
  **従うかどうかは自分で判断する**
- 夜間・雨天・不慣れな土地での初回テストは避ける
- 画面を見ながら歩かない(そもそも見ない設計)

## 7. うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 音が全く鳴らない | 画面の「音声: 稼働 / 停止」。停止なら AirPods を繋ぎ直す。「earcon の試聴」で単発の音を確認 |
| 提案が 1 度も鳴らない | 画面の「地図:」表示。`未読込` なら手順 2。初回の散歩は全方向が未踏で「直進が最良」になりやすく、鳴らないことがある |
| 案内が道の無い方を指す | 地図が入っているか。入っていて起きるなら**不具合**なので、経路図の番号を添えて報告 |
| うなずきが効かない | AirPods がモーション対応モデルか。画面の「モーション ○○ Hz」が出ているか。効かなければデバッグボタンで代替 |
| 実機ビルドが失敗する | iPhone のロック解除・「信頼」・Team ID(`OU` の値)。それでも駄目なら Xcode から直接 Run |
| 到着音が鳴らない | 自宅の設定位置と実際の到着位置がずれている可能性。`arrival_radius_m` を広げて試す |
| 帰路の案内が来ない | 地図が入っていないと道なりの案内は出ず、自宅を直線で指すビーコンだけになる |

## 8. いまの状態(期待値の調整)

**プロトタイプであって製品ではない。** 分かっている制限:

- 音はコード合成のサイン波。**デザインされた音ではない**
- **頭の向きは反映していない。** 首を振っても音は動かない
  (AirPods の yaw が旋回を追えなかったため。→ [docs/03](03_session_and_audio.md))
- 前後は聴き分けられない。真後ろは音色を暗くして代替している
- ジェスチャの首振り誤検出は約 9%。困るまで直さない方針
- 60 分を超える散歩・バックグラウンド動作の検証は薄い

**それでも「音の鳴る方に歩くと面白い散歩ができる」かどうかが、この試作で確かめたいこと。**
