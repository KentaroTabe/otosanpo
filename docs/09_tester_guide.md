# 09. テスターの手順書(iPhone)

**このアプリは画面を見ずに歩くもの**なので、スクリーンショットでは何も伝わらない。
実際に歩いてもらうしかない。

**配布は TestFlight。テスターに Mac も Xcode も要らない。**
招待を受け取って入れるだけで始められる。

所要時間の目安: **準備 5 分 + 散歩 20〜30 分**。

音だけ先に聴きたい場合は、開発者に紹介ページ(音の入った URL)を頼めば
歩かずに雰囲気は分かる → [docs/07](07_introducing.md)。

## 0. 用意するもの

| | 要否 | 補足 |
|---|---|---|
| iPhone(iOS 17 以降) | **必須** | シミュレータでは音の定位と GPS が確かめられない |
| TestFlight アプリ | **必須** | App Store から無料で入る。**入れていなくてよい**(手順 1 で入れる) |
| イヤホン | **必須** | 有線でもワイヤレスでもよい。**左右が分からないと成立しない**ため |
| AirPods(第 3 世代 / Pro / Max) | あれば | うなずき・首振りで答えられる。**無くても参加できる**(画面から答える) |
| 経路データ(`otosanpo-map.json`) | 推奨 | **開発者が作って渡す**。無くても動くが提案の質が落ちる |

**AirPods は必須ではない。** 使う場面はうなずき・首振りの応答だけで、
それは画面のボタンで置き換えられる。→ [AirPods を持っていない場合](#airpods-を持っていない場合)

ただし**イヤホンは要る**。このアプリは「音がどちらから鳴るか」で方向を伝えるので、
iPhone のスピーカーだと左右がほとんど分からない(音源が片側に集まっているため)。
有線イヤホンでも左右は分かるはずだが、**未確認**(実機で試したのは AirPods のみ)。

**歩ける場所**: 車の少ない住宅街や公園まわりが向く。片側 2 車線以上の道が多い地域だと
横断コストで提案が減る。

## 1. 入れる

**TestFlight を入れたことが無くて構わない。** ほとんどの人は入れていない。
Apple 純正の無料アプリで、アカウントを作る必要も課金も無い。

1. **App Store で「TestFlight」を検索して入れる**(既にあれば飛ばす)
   - 使うのは iPhone にいつも入れている Apple Account でよい
   - **Mac の TestFlight ではなく iPhone の TestFlight** を使う。
     このアプリは iPhone 専用なので、Mac の TestFlight には出てこない
2. 開発者から届いた**招待メールかリンク**を iPhone で開く
   - メールが見当たらない時は迷惑メールを確認する。それでも無ければ開発者に連絡する
   - 招待は**メールアドレス宛**に届く。開発者に伝えたアドレスで受け取ること
3. TestFlight が開くので「**受け入れる**」→「**インストール**」
4. 起動する

**「開発元を信頼」の操作は要らない。** ビルドは 90 日有効で、更新が出れば
TestFlight から通知が来て 1 タップで入れ替わる。

> TestFlight は配布のためだけに使う。**歩いている間は開かない。**
> 感想を送る口も付いているが(手順 5)、使わなくてよい。

## 2. 経路データを入れる(推奨)

経路データがあると、**実在する分岐から提案し、帰路を道なりに案内する**ようになる。
無い場合はセル単位の推測だけで動くので、「道の無い方向」を指すことがある。

**作るのは開発者側**(PC で OSM から切り出す)。受け取ったら:

1. `otosanpo-map.json` を AirDrop・メール・メッセージなどで iPhone に受け取る
2. 共有メニューから「**"ファイル"に保存**」
3. 保存先に「**この iPhone 内 > OtoSanpo**」を選ぶ

アプリの画面に `地図: 半径5km・2026-08-18` と出れば読めている。`地図: 未読込` なら入っていない。

> 作るには**散歩の中心(自宅など)のだいたいの座標**が要るので、開発者から聞かれる。
> 渡したくなければ「渡さない」でよい(経路データ無しでも歩ける)。

## 3. 散歩する

### 出発前

1. アプリを起動し、**位置情報**(アプリの使用中は許可)と**モーション**を許可する
   - AirPods が無い場合、モーションは許可しなくても動く(使う場面が無い)
2. イヤホンを装着する。AirPods なら**外音取り込み**にする
   (アプリからは制御できないので手で設定)。**安全のため必須と考えてほしい**。
   外音取り込みの無いイヤホンなら、**片耳だけにする**などで周囲の音を確保する
3. 自宅(出発点)で「自宅を現在地に設定」。初回は「ここを自宅にして散歩を開始」でもよい
4. 散歩時間を決める(既定 30 分)
5. 「散歩を開始」を押す。**時間帯に応じた一言が出る**ので、閉じて iPhone をポケットへ
6. 以後は画面を見ない
   - AirPods が無い場合だけ、**時間が来た音が鳴ったら一度だけ開く**(次節)

### 歩いている間に鳴る音(5 種)

| 音 | 意味 | いつ |
|---|---|---|
| 上行する 2 音(880→1175 Hz) | **こちらへ曲がると新しい道** | 前方 35 m 以内の交差点に近づいた時。角に近づくほど大きくなる |
| 上行する 3 音 | **時間になった。帰る?** | 「今から帰れば時間ちょうど」の瞬間 |
| 下行する 2 音(長め) | **帰路開始を受け付けた** | うなずきの直後 |
| 単発のピップ(440 Hz) | **帰る方向はこちら** | 帰路の間。歩調に同期して鳴り、自宅に近いほど大きい |
| 上行する 3 音(短い) | **到着** | 自宅 10 m 以内 |

- **提案は無視してよい。** 従わなくても叱られないし、鳴り続けもしない
  (角が背後に回ると止まる)
- 曲がる案内は**音の鳴る方に歩けば角に着く**ように作ってある。
  角に近づくにつれて、音は曲がる先へ移っていく
- 帰路は角も自宅も同じ音で鳴る。連続音なら「次の角」、間欠音なら「自宅の方向」

### 時間が来たら

上行 3 音が鳴ったら、**帰るか・もう少し歩くか**を答える。答え方は 2 つあり、
**どちらで答えても動きは同じ**。

**AirPods を着けている場合**(手を使わない)

- **うなずく** → 帰路開始
- **首を振る** → 延長(設定時間の 1/3。最大 2 回)

**画面から答える場合**(AirPods が無い / うなずきが検出されない)

1. iPhone をポケットから出してアプリを開く
2. 一番上に「**時間になりました**」が出ているので、
   「**帰る**」か「**もう少し歩く**」を押す
3. 画面を閉じてポケットへ戻す

答えるまでは 60 秒ごとに鳴り直す。**放っておいても勝手に帰らされることはない。**
AirPods を外している間は鳴らさず、付け直した時に鳴り直す。

### AirPods を持っていない場合

**参加できる。** AirPods が要るのは上の「うなずき・首振り」だけで、
それは画面のボタンで置き換えられる。違いはここだけ。

| | AirPods あり | AirPods なし |
|---|---|---|
| 提案・帰路の案内 | 音で鳴る | **同じ** |
| 左右・距離の伝わり方 | 音の向きと大きさ | **同じ**(イヤホンが要る) |
| 時間が来た時の答え方 | うなずく / 首を振る | **画面のボタン** |
| 頭の向きの反映 | していない(制限) | していない |

**歩いている間に画面を開くのは、時間が来た時の 1 回だけ。**
それ以外は AirPods のある人と同じく、ポケットに入れたままでよい。

> 「頭の向きを反映しない」のは今の実装の制限で、AirPods の有無とは関係が無い。
> つまり**この点では差が付かない**。→ [docs/03](03_session_and_audio.md)

## 4. 帰ってきたら

### 経路図を見る

アプリの「**前回の散歩(開発用)**」に距離・時間・イベント数が出る。
「経路図とイベントを見る」を開くと、歩いた経路と**番号を振った案内**が地図になる。

- 灰色の線 = 端末内の経路データの道
- 太い線 = 実際に歩いた経路
- 番号つきの丸 = 曲がる案内。**塗り = 曲がった / 白抜き = 曲がらなかった**
- 丸から伸びる矢印 = その案内が指した向き

**気になったことがあれば、この番号で指してもらえると特定が早い。**
「3 番目の案内が道の無い方を指した」のように書ければ、ログの該当箇所がすぐ出る。

### ログを書き出す

アプリの「フィールドログ > ログを書き出す」から AirDrop などで開発者へ。
次のテストの前には「ログを消去」を押すと、回ごとの切り分けが楽になる。

TestFlight の「フィードバックを送信」からスクリーンショット付きで送ることもできる
(クラッシュした場合は自動で届く)。

## 5. 感想の返し方

### 先に読んでほしいこと(プライバシー)

**フィールドログには緯度経度が入る。自宅の座標も含まれる。**

- ログを渡す相手は開発者本人に限る。**公開の Issue に貼らないこと**
- 出したくない場合は「渡さない」でよい。**文章の感想だけでも十分**役に立つ
- アプリは通信を一切しない。記録は端末から出ない(出すのは自分で書き出したときだけ)

### 何を書いてほしいか

**うまく言葉にできなくてよい。** 「なんか気持ち悪かった」で十分で、
ログと突き合わせれば原因は追える。特に知りたいのは:

1. **音のする方へ歩けたか。** 迷ったか、自然に曲がれたか
2. **左右が分かったか。** 分かりにくい場面があったか
3. **距離が分かったか**(音量で表している)。角の手前で「ここだ」と確定できたか
4. **うるさかったところ / 静かすぎたところ**
5. 帰路は不安なく帰れたか
6. **道の無い方向・私有地・危ない方向**を指した場面(あれば経路図の番号を添えて)

## 6. 安全について

- **外音取り込みを必ず使う。** 音楽と違って断続的だが、耳を塞ぐと環境音が聞こえにくい
- 提案は**歩ける道かどうかを地図で見ているだけ**で、交通量や工事は考慮していない。
  **従うかどうかは自分で判断する**
- 夜間・雨天・不慣れな土地での初回テストは避ける
- 画面を見ながら歩かない(そもそも見ない設計)

## 7. うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 招待メールが見つからない | 迷惑メールを確認。開発者に伝えたのと同じアドレスで受け取る。TestFlight の招待は**メールアドレス宛**で、App Store の検索には出てこない |
| Mac の TestFlight に出てこない | 正常。**iPhone 専用アプリ**なので Mac には出ない。iPhone の TestFlight を使う |
| 音が全く鳴らない | 画面の「音声: 稼働 / 停止」。停止ならイヤホンを繋ぎ直す。「earcon の試聴」で単発の音を確認 |
| 左右が分からない | イヤホンを使っているか。**iPhone のスピーカーだと左右はほぼ分からない** |
| 時間が来ても何も鳴らない | 設定時間より早く鳴ることはある(「今から帰れば時間ちょうど」で鳴るため)。アプリを開いて「時間になりました」が出ていないか確認 |
| 提案が 1 度も鳴らない | 画面の「地図:」表示。`未読込` なら手順 2。初回の散歩は全方向が未踏で「直進が最良」になりやすく、鳴らないことがある |
| 案内が道の無い方を指す | 地図が入っているか。入っていて起きるなら**不具合**なので、経路図の番号を添えて報告 |
| うなずきが効かない | AirPods がモーション対応モデルか。画面の「モーション ○○ Hz」が出ているか。効かなければ**画面の「時間になりました」から答える**(同じ動きになる) |
| 到着音が鳴らない | 自宅の設定位置と実際の到着位置がずれている可能性。開発者へ連絡(`arrival_radius_m` を広げる) |
| 帰路の案内が来ない | 地図が入っていないと道なりの案内は出ず、自宅を直線で指すビーコンだけになる |

## 8. いまの状態(期待値の調整)

**プロトタイプであって製品ではない。** 分かっている制限:

- 音はコード合成のサイン波。**デザインされた音ではない**
- **頭の向きは反映していない。** 首を振っても音は動かない
  (AirPods の yaw が旋回を追えなかったため。→ [docs/03](03_session_and_audio.md))
- 前後は聴き分けられない。真後ろは音色を暗くして代替している
- ジェスチャの首振り誤検出は約 9%。困るまで直さない方針
- 60 分を超える散歩・バックグラウンド動作の検証は薄い
- アイコンは仮のもの

**それでも「音の鳴る方に歩くと面白い散歩ができる」かどうかが、この試作で確かめたいこと。**
