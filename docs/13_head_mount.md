# 13. スマホ頭部固定の共通基盤(2026-08-29 設計)

iPhone をヘッドバンドで頭に固定し、**頭の絶対方位**を定位の基準にする。
方針 B(docs/14)と方針 C(docs/08)の両方が前提にする共通部分をここに置く。

なぜ成立するかの分析は docs/03「スマホを頭に固定する案」。要点:
**ヨーの絶対化には磁気か外部参照が要り、AirPods には磁力計が無い。スマホにはある。**
9 軸ユニットを自作して解こうとしていた問題が、手持ちの機材とヘッドバンド代で解ける。

**位置づけは実験装置**(docs/03 決定済み)。docs/01 のゴール
「iPhone + AirPods だけ」からは外れるため、配る形ではない。
**B / C の体験が成立するかを判定するための装置**として設計する。

## 取得

- `CMMotionManager.startDeviceMotionUpdates(using: .xTrueNorthZVertical)`。
  位置情報は常に取っているので真北基準が使える
- 読むのは `deviceMotion.heading`(0〜360°・真北基準)。
  **attitude の軸ではなく heading を使う** — 装着の向き(縦・横・多少の傾き)に
  依存させないため。取り付けのずれは定数 1 つ(`head_mount_offset_deg`)で引く
- Services に `HeadMotionService` を足し、既存の `HeadSample` の形で
  `WalkSessionController` へ流す。**Core は変えない** — 定位の基準は
  `placementReference()` に一本化済みで、`latestFacingBearing` に入れるだけ

## 磁気の乱れ(この装置の最大の敵)

頭に載せても磁力計は磁力計で、**鉄骨・車・線路の近くでは数十度ずれる**。
端末コンパスが帰路で左右を反転させた実測がある(docs/04・2026-08-16)。

**歩いている間は course と突き合わせて検疫する:**

- |heading − course| が `head_mount_distrust_deg` を超える状態が
  `head_mount_distrust_sec` 続いたら「乱れ」と判定し、**course 定位へ退避**する
- 復帰も同じ形(閾値の内側が続いたら戻す)。行き来が暴れないよう窓で見る
- 立ち止まっている間は突き合わせる相手が無い → **直前の信頼状態を引き継ぐ**
- 判定の実体は Core(`HeadingQuarantine`・純粋)。閾値は parameters.json

ログには従来の `顔=` 列に heading を、方向の出所ラベルに「頭部(実測)/ 退避」を出す。
**散歩 1 回で「乱れが実際どれだけ起きるか」の分布が取れる**(replay で集計)。

## ジェスチャ

phone の pitch / heading の変化を既存の `HeadGestureDetector` に流せば、
うなずき・首振りが **AirPods 非依存**になる見込み。

- iOS: AirPods 装着中はどちらでも取れる。優先順位は判断待ち
- **Android に効く**: TYPE_HEAD_TRACKER(対応機器がほぼ無い)を待たずに
  ジェスチャが動く道が開ける(docs/10 判断待ち 1)

## 未確認(机上で先に潰す)

| # | 確認 | 方法 | これが駄目なら |
|---|---|---|---|
| 1 | **画面消灯・ポケット無しの頭上で 50 Hz が続くか** | 頭に固定し画面を消して「頭の追従の確認」を数分 | 背景モードの見直し。audio+location はあるが CMMotionManager の挙動は**未確認** |
| 2 | 首振りへの追従と符号 | 「頭の追従の確認」を絶対方位モードで。首を右→音が左 | 取り付け定数か軸の読み違い。机上で直る |
| 3 | 屋内の磁気で狂うか | スチール家具・冷蔵庫の近くで 2 を繰り返す | 検疫の閾値を実測から決める材料になる |
| 4 | 歩調センサへの影響 | 散歩 1 回(頭上の CMPedometer が歩数を出すか) | ビーコン間隔が fallback(2 秒)に落ちる。iPhone を**ポケットに残し**、頭は別問題として測る手もある |
| 5 | 電池・発熱 | 散歩 1 回の受動観察 | 実験の長さを制限する |

4 は装置の構成に関わる: **「頭に載せるのは方位のためだけ」なら、
iPhone 2 台目や「音は AirPods・本体はポケット」構成は取れない**
(1 台しか無い)。頭上の歩数検出が動くかが構成を決める。

## 装着

- ヘッドバンド + 固定。落下・雨・汗は割り切る(実験装置)
- 画面は額にあるので**歩行中は見えない**。画面が要る操作(方針 C の柱 4)は
  装着の前後に寄せる → docs/08 の改訂

## パラメータ(案・すべて parameters.json)

```
head_mount: {
  enabled: false,            // 既定 off。装置を着けた実験でだけ on
  offset_deg: 0,             // 取り付けの向きの補正(定数)
  distrust_deg: 40,          // course との差がこれを超えたら乱れを疑う
  distrust_sec: 5,           // 超過がこれだけ続いたら退避
  regain_sec: 5              // 内側がこれだけ続いたら復帰
}
```

数値はすべて仮置き。確認 3(屋内の磁気)と散歩 1 回の分布から決める。
