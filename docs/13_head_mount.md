# 13. スマホ頭部固定の共通基盤(2026-08-29 設計)

iPhone をヘッドバンドで頭に固定し、**頭の絶対方位**を定位の基準にする。
方針 B(docs/14)と方針 C(docs/08)の両方が前提にする共通部分をここに置く。

なぜ成立するかの分析は docs/03「スマホを頭に固定する案」。要点:
**ヨーの絶対化には磁気か外部参照が要り、AirPods には磁力計が無い。スマホにはある。**
9 軸ユニットを自作して解こうとしていた問題が、手持ちの機材とヘッドバンド代で解ける。

**位置づけは実験装置**(docs/03 決定済み)。docs/01 のゴール
「iPhone + AirPods だけ」からは外れるため、配る形ではない。
**B / C の体験が成立するかを判定するための装置**として設計する。

## 取得

- `CMMotionManager.startDeviceMotionUpdates(using: .xTrueNorthZVertical)`。
  位置情報は常に取っているので真北基準が使える
- 読むのは `deviceMotion.heading`(0〜360°・真北基準)。
  **attitude の軸ではなく heading を使う** — 装着の向き(縦・横・多少の傾き)に
  依存させないため。取り付けのずれは **course との差の定常成分として歩きながら学習する**(→ MountOffset・2026-09-01)
- Services に `HeadMotionService` を足し、既存の `HeadSample` の形で
  `WalkSessionController` へ流す。**Core は変えない** — 定位の基準は
  `placementReference()` に一本化済みで、`latestFacingBearing` に入れるだけ

## 磁気の乱れ(この装置の最大の敵)

頭に載せても磁力計は磁力計で、**鉄骨・車・線路の近くでは数十度ずれる**。
端末コンパスが帰路で左右を反転させた実測がある(docs/04・2026-08-16)。

**歩いている間は course と突き合わせて検疫する:**

- |heading − course| が `head_mount_distrust_deg` を超える状態が
  `head_mount_distrust_sec` 続いたら「乱れ」と判定し、**course 定位へ退避**する
- 復帰も同じ形(閾値の内側が続いたら戻す)。行き来が暴れないよう窓で見る
- 立ち止まっている間は突き合わせる相手が無い → **直前の信頼状態を引き継ぐ**
- 判定の実体は Core(`HeadingQuarantine`・純粋)。閾値は parameters.json

ログには従来の `顔=` 列に heading を、方向の出所ラベルに「頭部(実測)/ 退避」を出す。
**散歩 1 回で「乱れが実際どれだけ起きるか」の分布が取れる**(replay で集計)。

## ジェスチャ

phone の pitch / heading の変化を既存の `HeadGestureDetector` に流せば、
うなずき・首振りが **AirPods 非依存**になる見込み。

- iOS: AirPods 装着中はどちらでも取れる。優先順位は判断待ち
- **Android に効く**: TYPE_HEAD_TRACKER(対応機器がほぼ無い)を待たずに
  ジェスチャが動く道が開ける(docs/10 判断待ち 1)

## 未確認(机上で先に潰す)

| # | 確認 | 方法 | これが駄目なら |
|---|---|---|---|
| 1 | **画面消灯・ポケット無しの頭上で 50 Hz が続くか** | 頭に固定し画面を消して「頭の追従の確認」を数分 | 背景モードの見直し。audio+location はあるが CMMotionManager の挙動は**未確認** |
| 2 | 首振りへの追従と符号 | 「頭の追従の確認」を絶対方位モードで。首を右→音が左 | 取り付け定数か軸の読み違い。机上で直る |
| 3 | 屋内の磁気で狂うか | スチール家具・冷蔵庫の近くで 2 を繰り返す | 検疫の閾値を実測から決める材料になる |
| 4 | 歩調センサへの影響 | 散歩 1 回(頭上の CMPedometer が歩数を出すか) | ビーコン間隔が fallback(2 秒)に落ちる。iPhone を**ポケットに残し**、頭は別問題として測る手もある |
| 5 | 電池・発熱 | 散歩 1 回の受動観察 | 実験の長さを制限する |

4 は装置の構成に関わる: **「頭に載せるのは方位のためだけ」なら、
iPhone 2 台目や「音は AirPods・本体はポケット」構成は取れない**
(1 台しか無い)。頭上の歩数検出が動くかが構成を決める。

## 装着

- ヘッドバンド + 固定。落下・雨・汗は割り切る(実験装置)
- 画面は額にあるので**歩行中は見えない**。画面が要る操作(方針 C の柱 4)は
  装着の前後に寄せる → docs/08 の改訂

## パラメータ(実装済み・すべて parameters.json)

```
head_mount: {
  enabled: false,                // 既定 off。装置を着けた実験でだけ on
  update_hz: 10,                 // スマホのモーション更新頻度
  distrust_deg: 40,              // course との差がこれを超えたら乱れを疑う
  distrust_sec: 5,               // 超過がこれだけ続いたら退避
  regain_sec: 5,                 // 内側がこれだけ続いたら採用(復帰)
  offset_min_samples: 200,       // ずれの学習に要る実効標本量(10 Hz で ≈ 20 秒)
  offset_half_life_sec: 300,     // ずれの平均の半減期(付け直しへゆっくり追従)
  offset_min_concentration: 0.8, // 「ずれが定数である」と認める合成ベクトル長 R の下限
  log_interval_sec: 1            // 「頭方位」行を残す間隔
}
```

**`offset_deg`(固定値)は廃止した**(2026-09-01・利用者判断)。決め忘れると検疫が
全部棄てて散歩が無駄になる失敗を実際に踏んだため、ずれは歩きながら学習する(下記)。
数値は仮置き。散歩の分布から再生で決める。

## 実装(2026-08-30)

帽子固定の初試行(2026-08-30・docs/05)で「頭とスマホの動きは対応させられそう」と
体感が得られたのを受け、**数値の裏付けを取るためのログと配線**を実装した。

| 置き場 | もの |
|---|---|
| Services | `HeadMotionService` — `CMMotionManager` + `.xTrueNorthZVertical`、`heading` を流すだけ |
| Core | `HeadingQuarantine` — 検疫の状態機械(純粋・テスト 8 件) |
| App | 散歩の開始 / 終了で起動・停止。検疫を通った時だけ `latestFacingBearing` へ |

設計からの確定事項:

- **初期状態は「未検証」= 使わない。** 信頼は course と合う実績(`regain_sec`)から得る。
  屋内の乱れた磁気で歩き出しても、最初の音が反転して鳴らない。
  散歩をまたいで信頼を持ち越さない(毎回白紙から)
- 検疫を通らない間は従来どおり進行方位で定位する。
  **enabled のまま装置を外して歩けば A/B 比較になる**(docs/14 の要件)
- 立ち止まり(course なし)では状態を保ち、**実績の窓は捨てる**
  (中断を挟んだ 3 秒 + 3 秒を 6 秒の実績として繋がない)

### ログ(次の散歩で取れるもの)

- `頭方位 heading=X° course=Y° 差=Z° 状態=未検証/採用/退避` を 1 秒間隔で記録。
  **heading と course の対があるので、`distrust_deg` 等の閾値は再生で振り直せる**(歩き直し不要)
- 画面の状態行に `頭部: 採用/退避/未検証` を常時表示(退避が出続ける = 磁気が乱れている)
- 「頭の追従の確認」(机上)にスマホ方位の生値を追加表示。
  **確認 2(追従と符号)・確認 3(屋内の磁気)はここでできる**
  (取り付けのずれは机上では決めない — 歩きながら自動学習する。下記)

### 取り付けのずれは自動学習(2026-09-01・利用者判断で固定値を廃止)

`MountOffset`(Core・純粋): heading − course の**円平均**を減衰つきで追い、
「量(実効標本 ≥ min_samples)」と「質(合成ベクトル長 R ≥ min_concentration)」の
両方が立った時だけ補正として使う。

- **学習が立つまでは補正 0 → 検疫が棄てる → 従来どおり進行方位で定位。**
  壊れた方位が音に出る経路が無い
- R の門があるので、**ポケットの中(向きが揺れる)や磁気の乱れからは学習しない**。
  装置を外して歩けばそのまま A/B 比較になる、という性質も保たれる
- 散歩ごとに白紙から学習し直す(付け直しで変わるため)。半減期 300 秒で
  散歩中の付け直しにもゆっくり追従する
- 学習は**生の方位**で行う(補正後を食わせると自分の出力を追いかけて循環する)

**2026-09-01 のログで再生検証**: 歩き出し 81 秒で学習が立ち、学習値 +93.5°
(オフライン推定 +93.8° と一致)、検疫の採用 78%(固定値 94° の手動設定なら 83%)。
ログの `頭方位` 行に `補正=`(学習値 or 学習中)と `R=` を追加した。

### 次の散歩の手順(実験)

1. 机上: `enabled: true` にし「頭の追従の確認」で**追従と符号**だけ見る
   (首を回して数字が滑らかに追うか・北で 0° 近辺か)。**ずれの設定は不要**(自動学習)
2. 散歩 1 回(帽子固定)。最初の 1〜2 分は学習中(進行方位で定位)。意図的に試すのは
   **「交差点で立ち止まって首を回し、音が世界に固定されて聞こえるか」** 1 つ
   (学習が立った後半で試す。画面の「頭部: 採用」が目印)
3. ログの `頭方位` 行から、閾値(distrust_deg / sec)と学習の条件を再生で決める

### 初回ログの実測(2026-09-01)— 自動学習に切り替えた経緯

- **offset を入れずに歩くと、ずれは一定の +94°** だった(その取り付き方の定数。
  符号つき円平均 +93.8°・391 件)。検疫が 84% 退避し、頭部基準はほぼ使われなかった
  — **未補正の方位から利用者を守る、という設計どおりの振る舞い**
- **offset を 94° に補正して再生すると採用 83%・残差の中央値 9.2°**(90% 点 40°)。
  頭上の磁力計は屋外ではかなり素直で、方位の質は B の土台に足りる見込み
- 当初の教訓は「机上の offset 決めは飛ばせない」だったが、**飛ばしても気づけない**
  (course 退避で普通に歩けてしまう)以上、手順で守るのは筋が悪い。
  **固定値を廃止して自動学習に切り替えた**(上記・利用者判断)
