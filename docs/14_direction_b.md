# 14. 方針 B: 道の先から音がする(2026-08-29 設計)

docs/06 の 3 方針のうち B。**通るべき道の先の方から音がして、そちらへ導かれる。**
頭部固定(docs/13)を前提に設計する。音そのものは**現行の earcon から変えない**
(利用者指示・2026-08-29)。

## 一言でいうと

**帰路のビーコンを、散歩全体に一般化する。**

帰路は既に「経路の場(RouteField)が指す道の上の向きへ、歩調同期のピップが鳴る」
形で動いている。B はこれを散策にも適用する。**散策も帰路も同じ「先導ビーコン」で、
違うのは行き先だけ**(散策 = 新鮮な地帯 / 帰路 = 自宅)。

| | 方針 A(現行) | 方針 B |
|---|---|---|
| 散策中の音 | 分岐提案 + 曲がり角の誘導(角の周辺だけ) | **先導ビーコン**(常時・間欠) |
| 直進 | 無音 = 「そのまま」の合図 | 前方から間欠音が続く |
| 曲がり角 | 誘導が角を指す(イベント) | **音源が先に角を曲がる**(連続) |
| 帰路 | 先導ビーコン | 同じ(変更なし) |
| 音の種類 | 5 種 | **同じ 5 種**。ピップの意味が「こちらへ」に統一される |

## A の最大の失敗が、構造的に消える

A の予告(1 音目で曲がる先を指す)は、実測で **20 件中 15 件が「進める道の無い向き」**
を指して廃止になった(docs/05・2026-08-25)。角に着く前に曲がった先を指す以上、
幾何的に避けられなかった。

B の音源は**場を道なりに辿った先の点**なので、**定義上つねに道の上にある**。
「音の鳴る方に歩けば道がある」が機構として保証される。

## 仕組み

```
行き先の選定(既存)     ZoneMap が「未踏で道のある地帯」を選ぶ
        ↓
場の構築(新)          goal = 行き先 の RouteField をもう 1 本作る
        ↓                (自宅向けの場と同じ機構。構築 0.4〜0.7 秒・背景)
音源の位置(新)         現在地から場を lure_lookahead_m(仮 80 m)だけ
        ↓                道なりに辿った点。歩くと先へ滑る(ニンジン)
鳴らす(既存)           homeBeacon のピップ・歩調同期・頭部基準の定位
```

- **経路から外れても再計算しない。** 場はどの節点にも答えを持っている(叱らない)。
  外れた位置からも「次の一歩」が引けるのは、帰路で実証済みの性質
- 行き先に近づいたら(`target_reached_m`・既存)次の行き先を選ぶ。
  音量は行き先への近さで上げる(近づく実感 = 到着の合図を兼ねる)
- 時間到来・応答・帰路・到着は**現行のまま**。帰路に入ると goal が自宅に変わるだけ
- 散策中の `BranchSuggester` / `TurnGuidance` は B では使わない
  (役割ごと先導ビーコンが吸収する)

## 頭部固定が効く場面

**交差点で立ち止まって「どっちから聞こえる?」と探す瞬間**が、この方式の核心で、
現行の course 定位では最悪の場面だった(立ち止まると course が失われ、
15 秒のホールドの後は方向なし)。頭部固定の絶対方位は GPS と無関係なので、
**立ち止まって首を回すと音源が世界に固定されて聞こえる**。

頭部固定なしでも動く(course 定位に退避 = 今のビーコンと同じ品質)。
**同じビルドで装着あり / なしを比べられる**ようにしておく(docs/13 の enabled)。

## 「基本無音」との緊張(設計上の最大の論点)

docs/01 の音の基本方針は「基本無音・点の earcon」。B は散策中も間欠音が続くので、
**この原則に正面から触れる**(連続 BGM ほどではないが、静けさは失う)。

緩和案:

- 間隔を疎にする(仮: `lure_steps_per_tone` = 8 歩に 1 音。帰路の 4 歩より疎)
- **まっすぐな区間ほど疎に、角の接近で密に**(ガイガー方式の一般化)。
  「次に曲がる地点」は場から引ける(`RouteField.nextTurn` 相当は帰路の誘導で実装済み)
- 上限音量は帰路ビーコンと同じ

**どこまで疎にしても「導かれている」感が保てるか**は、歩かないと分からない。
これが B の実験の主目的になる。

## パラメータ(案)

```
direction_b: {
  enabled: false,          // A/B はブランチではなく設定で切り替える(同じ端末で比較)
  lure_lookahead_m: 80,    // 音源を先へ置く距離
  lure_steps_per_tone: 8,  // 間欠の疎密(直進時)
  lure_gain_far: 0.4,      // 行き先が遠いときの音量
  lure_gain_near: 1.0
}
```

すべて仮置き。ブランチを分けず**設定で切り替える**のは、散歩 1 回の中で
A と B を切り替えて比べられるようにするため(装置の付け外しより設定が軽い)。

## 実装の切れ目

| 段 | やること | 確かめ方 |
|---|---|---|
| 0 | **机上: lure 点の再生** | 過去のログの経路に対して lure 点の軌跡を計算し、**道の上率 100%** と「角で先に曲がる」ことを replay で確認。**歩かない** |
| 1 | goal 付き場の管理(Core) | 既存 RouteField をそのまま使う。行き先の変更で作り直す管理をテスト |
| 2 | 先導ビーコンの配線(App) | シミュレータ + 机上 |
| 3 | 散歩 1 回 | **頭部固定あり / なし・A / B を同じ散歩で切り替えて比較**。意図的に試すのは「立ち止まって方向が分かるか」1 つ |
