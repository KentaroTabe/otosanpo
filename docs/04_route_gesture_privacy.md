# 04. 経路モデル・ジェスチャ・プライバシーと安全

## 通過履歴グリッド(VisitGrid)

- 約 `cell_size_m`(50 m)四方のセル単位で通過回数を保持
- 通過で +1、`visit_half_life_days`(45 日)の半減期で指数減衰
  - 効果: 半年通らなかった道は自動的に「新鮮な候補」へ戻る。手動メンテ不要
- 通勤路の除外: **学習モード**(ContentView のトグル)を ON にして移動すると、その経路のセルに `excluded` が付き、以後は常に高い馴染み度(`excluded_familiarity` = 8.0)として扱われ提案されない
  - 地図をなぞる登録 UI は完成品スコープ(P2)。学習モードはその補助輪に相当する
- プロトタイプはセルベース。完成品では OSM way 単位のカウンタに置き換える(docs/01 ロードマップ)

## 進行方向の取得(TravelDirection)

提案もビーコンも「いま体がどちらを向いているか」を基準に左右を決めるため、基準の取り方が体験の正否を左右する。

- iPhone はポケットに入る前提なので、**端末の磁気コンパス(CLHeading)は進行方向の代用にならない**(端末の向き ≠ 進む向き)
- 第一候補は `CLLocation.course`(移動の軌跡から出る方向)。次の条件をすべて満たすときのみ採用する
  - 速度が `min_speed_for_course_m_per_s`(0.7 m/s)以上 = 実際に歩いている
  - 位置更新からの経過が `max_fix_age_sec`(10 秒)以内
  - `courseAccuracy` が `max_course_accuracy_deg`(45°)以内(不明な場合は精度判定をしない)
- 上記を満たさない間(静止中・GPS 不良)は `allow_compass_fallback`(true)ならコンパスへ退避する。退避中は左右が実際の体の向きとずれ得るため、イベントログとフィールドログに方向の出所を必ず残す
- どちらも使えない場合は提案を鳴らさず、ビーコンはパンなし(中央)で鳴らす

## 提案スコアリング(BearingSuggester)

進行方向を基準に {直進, 左右 45°, 左右 90°} の 5 候補を評価する。

```
novelty(dir)  = 1 / (1 + 扇形内の平均馴染み度)          ∈ (0, 1]
score(dir)    = novelty(dir) − homewardBias × (自宅方位との角度差 / 180)
```

- 扇形: 幅 `sector_width_deg`(60°)、半径 `sector_radius_m`(250 m)
- **最良が直進なら鳴らさない**(直進に音は要らない。曲がる価値がある時だけ鳴る)
- 最良スコアが `suggestion_min_score` 未満でも鳴らさない(馴染んだ地帯では静かになる=仕様)
- 帰宅バイアスが上がると、自宅方向の候補が自然に勝つようになる

## 頭ジェスチャ検出(HeadGestureDetector)

- 入力: AirPods の姿勢(pitch / yaw、度)
- 窓 `window_sec`(1.6 秒)内のサンプルについて、(min+max)/2 を基準とした偏差が閾値(nod: ±10°、shake: ±12°)を跨いで符号反転した回数を数え、`min_reversals`(2 回)以上で検出
- 検出後 `refractory_sec`(1 秒)は再検出しない
- 誤検出対策:
  - promptingReturn 状態のときだけ検出を有効化(常時検出しない)
  - 歩行中の体の回転(yaw の単調変化)は反転を生まないため首振りと区別される
  - **±180° の折り返し解除**: CoreMotion の yaw は -π..π で表されるため、正面がその境界付近にあると数度の揺れが約 360° のジャンプとして現れ、首振りに化ける。隣接差が ±180° を超えた分を打ち消してから反転を数える
- 閾値は仮置き。フィールドテストで実測調整する(未検証)
- **検出には往復 1.5 回ぶんの動きが要る**: `min_reversals`(2)は「基準線を跨ぐ符号反転が 2 回」を意味し、ゆっくり 1 回うなずくだけでは満たさないことがある。また閾値 ±10° は振幅で 20° を要求する
- 切り分け用に、`diagnostics_interval_sec`(0.5 秒)ごとにサンプリング頻度と実測振幅を画面とフィールドログへ出す。「サンプルが届いていない」のか「振幅が足りない」のかを区別するための計測
- 応答待ち以外(歩行中など)は、検出に必要な振幅の `diagnostics_report_ratio`(0.7)倍を超えた区間だけ「誤検出候補」として記録する。閾値を下げられる余地は、この分布が意図的な動作の振幅と重ならないかで判断する

## プライバシー

- 位置履歴(VisitGrid)と自宅座標は**端末内にのみ保存**(Application Support / UserDefaults)。送信コードは存在しない
- フィールドログ(`Documents/otosanpo-field-log.tsv`)は時刻・状態・座標・メッセージを追記する開発用の記録。端末内にのみ保存し、書き出すかどうかは利用者の操作(共有シート / Finder)に委ねる。ContentView から消去できる
- バックグラウンド位置利用中はステータスバーに明示(`showsBackgroundLocationIndicator = true`)
- 権限文言にも「端末内にのみ保存」を明記(project.yml の Info properties)

## 安全

- 基本無音・点の earcon・外音取り込み前提により、環境音(車の接近など)をマスクしない
- プロトタイプは**道路種別を把握しない**。交通量の多い道への誘導を避ける仕組みは未実装であり、テスト時は歩行者が安全に歩けるエリアで行うこと(既知の制限)
- 完成品では OSM の歩道情報・道路種別をスコアに組み込み、幹線道路への提案を抑制する(P2)
